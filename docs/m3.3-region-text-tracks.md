# M3.3 independent region text tracks

M3.3 replaces scene-lifetime geometry with independent, event-keyframed text regions while
keeping schema-v1 manifests readable.

## Design

The schema-v2 manifest keeps the original contiguous `tracks` array for auditability and adds
`region_tracks`. Each region track owns one approved translation, its independent visible
interval, and ordered normalized bbox keyframes. A keyframe declares either `hold` or `linear`
interpolation to the following keyframe.

The tracking command combines two existing artifacts:

1. schema-v1 scene tracks provide reviewed translations and retained OCR, including regions
   previously ignored by the static OCR mask;
2. the M3.2 visual-event index selects one stable pre-frame, each changed frame, and one stable
   post-frame only for sufficiently large, short events;
3. PaddleOCR runs on the changed-tile union, using the visual-event exclusions rather than the
   static central OCR exclusion;
4. Unicode-normalized fuzzy text association reuses approved translations and never loads the
   translation model;
5. vertical-scroll events stabilize horizontal text geometry and insert an exact event-start
   hold keyframe before movement begins.

Run the audited `0.mp4` subsection:

    text-localizer track-regions `
      data\output\0-m23-timeline\tracks.json `
      data\work\0-m32-visual-events\visual-events.json `
      --profile config\profiles\browser-lecture.yaml `
      --output data\output\0-m33-region-tracks `
      --work-dir data\work\0-m33-region-tracks `
      --start-seconds 120 `
      --end-seconds 166.8

The command writes `tracks.json` and a frame-synchronized `viewer.html`. OCR observations are
saved per frame and reused after interruption or association changes.

## Measured CPU run

The unchanged 175.275102-second `0.mp4` was tested on Windows Python 3.12.9 and CPU only.
The selected window contains three significant scroll events.

| Metric | Result |
| --- | ---: |
| Full visual-event samples available | 877 |
| OCR frames selected | 11 |
| Summed PaddleOCR latency | 493.131 s |
| Median PaddleOCR latency per frame | 45.251 s |
| OCR regions matched / unmatched | 183 / 88 |
| Region tracks affected | 20 |
| Total independent region tracks | 33 |
| Translation-model calls | 0 |

This is the practical CPU boundary: running OCR on all 877 samples would be unreasonable, but
event-gated OCR is slow yet tractable and fully resumable.

## Temporal result

Ground-truth revision 2 corrects a benchmark annotation error found by opening the exact source
frames: the prior LangChain boxes were each paired with the following scroll state. Re-running
the unchanged schema-v1 baseline after that correction still fails coverage and recall, while
its already-visible boxes are spatially accurate.

| Metric | Corrected v1 baseline | M3.3 v2 | Gate |
| --- | ---: | ---: | ---: |
| Annotation recall | 66.67% | 100% | >=95% |
| Keyframe recall | 66.67% | 100% | >=95% |
| P95 boundary error | 37.5 ms | 37.5 ms | <=67 ms |
| Median bbox IoU | 0.964 | 0.916 | >=0.75 |
| Flicker events | 0 | 0 | 0 |
| All gates | FAIL | PASS | PASS |

The bbox median decreases slightly because M3.3 now evaluates all moving keyframes instead of
only the easy pre-scroll subset. Every LangChain keyframe still exceeds 0.85 IoU.

## Compatibility and safeguards

- `validate_track_manifest` accepts v1 and v2; the evaluator chooses region keyframes for v2.
- The viewer interpolates v2 geometry from decoded video-frame media time and preserves the v1
  scene-track path unchanged.
- The original MP4 is read-only and remains unchanged.
- Frames, observations, manifests, models, and generated HTML stay ignored by Git.
- Schema-v2 keyframe editing and MP4 burn-in are not yet implemented. The CLI refuses to
  silently render v2 through the old static scene path; use `viewer.html` for M3.3 review.

M3.4 extends this output with translation-anchored OCR consensus, event-backed lifecycle closure,
disjoint OCR windows, and absence-aware temporal gates. See `m3.4-quality-foundation.md`.
