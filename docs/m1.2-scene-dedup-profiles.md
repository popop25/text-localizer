# M1.2 profiles and scene deduplication

## Goal

M1.2 makes M1.1 analysis settings reusable and identifies repeated static screens before
OCR. It does not run OCR automatically, delete frames, or generate time-based overlay
tracks.

## Localization profile

A schema-versioned YAML profile stores:

- a normalized OCR ROI;
- repeatable normalized exclusion regions;
- minimum text height, grouping, and translation batch settings;
- a glossary path resolved relative to the profile;
- dHash size and Hamming-distance threshold.

`analyze-image --profile` uses these values. Explicit CLI values override the profile,
while CLI `--exclude-roi` values append to the saved exclusions. The checked-in
`config/profiles/browser-lecture.yaml` profile represents the tested browser-lecture
layout and masks both the presenter card and bottom-right presenter video.

## Scene index

`deduplicate-frames` performs these steps without loading OCR or translation models:

1. sort images matching the requested filename pattern;
2. crop the saved ROI;
3. black out exclusion intersections;
4. resize the result and compute a 256-bit dHash by default;
5. compare each frame with the current scene anchor;
6. create a new scene when Hamming distance exceeds the configured threshold;
7. write every decision to JSON without modifying the frames.

Each frame records its hash, scene ID, representative path, distance to the scene anchor,
distance to the previous frame, and whether it became a representative. The report also
records unique and duplicate counts, reuse ratio, and hashing latency.

## Commands

```powershell
text-localizer analyze-image data\work\0-frames\frame-0005.png `
  --profile config\profiles\browser-lecture.yaml `
  --output data\output\frame-0005

text-localizer deduplicate-frames data\work\0-frames `
  --profile config\profiles\browser-lecture.yaml `
  --output data\work\0-scene-index.json
```

The scene command also accepts `--pattern`, `--roi`, `--exclude-roi`, `--hash-size`, and
`--hamming-threshold`. CLI ROI replaces the saved ROI; CLI exclusions append.

## Measured sample

On 12 evenly spaced frames from the 175-second Korean browser lecture:

- 9 unique scene anchors were retained;
- 3 frames were reused, for a 25% reuse ratio;
- frame pairs 0004/0005, 0007/0008, and 0010/0011 shared scenes;
- reused-frame anchor distances were 4, 0, and 16;
- the smallest observed real-transition distance was 44;
- the browser-lecture threshold was therefore set to 18 while the global default remains
  the more conservative 12.

The resulting ignored data file is `data/work/0-scene-index.json`.

## Limitations and next step

- The input frames are evenly spaced and do not yet carry timestamps in their filenames or
  a manifest.
- dHash detects screen similarity, not semantic equivalence.
- A profile is layout-specific; coordinates should be reviewed when the window or player
  layout changes.
- Gradual scrolling can produce multiple legitimate scene anchors.
- This milestone indexes decisions but does not invoke OCR only for representatives.

The next step should extract timestamped frame samples, run M1.1 only for scene anchors,
and emit a preliminary time-range track manifest for the browser player.
