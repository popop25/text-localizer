# M2.2 exact timestamp sampling

M2.2 makes each declared fixed-interval timestamp refer to the frame actually sampled at that
time. It also prevents stored OCR from being resumed after a representative frame is replaced
in place, and restores the broken `render-tracks` command discovered during full-video QA.

## Failure reproduced

The prior one-second batch extraction used FFmpeg's default `fps` rounding. The manifest
declared `frame-000140.png` as 140.000 seconds, but the pixels matched a direct extraction at
140.500 seconds:

- the old batch frame exactly matched `fps ... round=near`;
- `round=up` exactly matched a direct 140.000-second extraction;
- the old run emitted 175 frames for a 175.275102-second video even though the authoritative
  timestamps are 0 through 175, or 176 frames.

This half-second displacement, rather than an untracked smooth-scroll scene, caused the
visible 140-second overlay drift reported in M2.1.

## Sampling contract

The implemented contract is explicit and resumable:

1. `interval_timestamps` produces the authoritative timestamps and expected frame count.
2. FFmpeg uses `fps=fps=1/<interval>:start_time=0:round=up`.
3. Extraction fails if FFmpeg's output count differs from the expected count.
4. The samples manifest uses schema version 2 and records
   `sampling_policy: fps-round-up-v1`.
5. Resume requires the exact schema, policy, frame count, indices, and timestamps.
6. A per-scene analysis is reused only when its saved `source.<suffix>` copy still matches
   the current representative frame by size and SHA-256. Replacing pixels at the same path
   therefore triggers fresh OCR instead of accepting stale geometry.

Full-video validation also exposed an unrelated CLI control-flow regression: `render-tracks`
was registered by argparse but fell through to `Unknown command`. Its viewer/editor branch
now returns before `render-video`, with a command-level regression test.

## Remaining limitations

A one-second base interval can still miss a visual state that appears and disappears entirely
between adjacent samples. Boundary bisection improves the timing of detected changes but does
not discover an unseen intermediate state. Automatic glossary protection can still require
human review when a generative translation drops a protected term. Generated frames, analysis
data, reviewed manifests, media, ASS, reports, and QA images remain ignored by Git.
