# M1.4 refined boundaries and local track editing

M1.4 narrows detected scene transitions without adding OCR calls and adds an offline browser
editor for the generated Japanese overlay tracks. The original MP4 is referenced in place and
is never rewritten.

## Boundary refinement

The fixed-interval scene index already identifies each transition between a previous sample
and a following sample. With `--boundary-refinement-iterations 3`, the indexer:

1. extracts the midpoint frame for each transition bracket;
2. hashes the same configured ROI and exclusion masks used by scene deduplication;
3. compares the midpoint hash with both adjacent scene representatives;
4. keeps the matching half of the bracket; and
5. repeats three times.

A one-second sample interval therefore becomes a maximum 0.125-second transition bracket.
The decision log, hashes, distances, extracted frame paths, and final bracket are stored under
`boundary_refinement` in both `scene-index.json` and `tracks.json`. This stage does not
load the OCR or translation models.

```powershell
text-localizer index-video data\input\0.mp4 `
  --profile config\profiles\browser-lecture.yaml `
  --work-dir data\work\0-m13-timeline `
  --sample-interval 1 `
  --boundary-refinement-iterations 3

text-localizer localize-video data\input\0.mp4 `
  --profile config\profiles\browser-lecture.yaml `
  --work-dir data\work\0-m13-timeline `
  --output data\output\0-m13-timeline `
  --sample-interval 1 `
  --boundary-refinement-iterations 3
```

## Track editor workflow

`localize-video` now writes two browser artifacts:

- `viewer.html`: playback with approved Japanese overlays; review-flagged regions stay hidden;
- `editor.html`: edit Japanese text, approve or reject regions, adjust contiguous scene
  boundaries, import track JSON, and export `tracks.edited.json`.

Open `editor.html` directly, review the tracks, and use **Export edited JSON**. The browser
downloads a new JSON file and never overwrites the pipeline output automatically. Validate an
edited file and regenerate both browser artifacts with:

```powershell
text-localizer render-tracks $HOME\Downloads\tracks.edited.json `
  --output data\output\0-m13-edited
```

Use `--video D:\path\to\moved-video.mp4` when the source video moved after the manifest was
created. Validation rejects duplicate track IDs, invalid normalized boxes, invalid review
fields, gaps or overlaps, and timelines that do not cover the complete video duration.

## Full-video measurement

Measured on the user-supplied 175.275102-second Korean lecture `0.mp4`, Windows native,
Python 3.12.9, CPU only:

| Measurement | Result |
| --- | ---: |
| Timestamped one-second samples | 175 |
| Unique scenes / tracks | 28 |
| Refined transitions | 27 |
| Extra boundary frames on first run | 81 |
| Extra boundary frames reused on resume | 81 |
| Maximum transition bracket width | 0.125 s |
| Mean absolute shift from the following sample | 0.1921 s |
| Existing scene analyses reused | 28 / 28 |
| Remaining automatic review flags | 1 |
| Track coverage | 0.000000–175.275102 s, contiguous |

The first boundary run took 112.4 seconds for FFmpeg extraction and hashing on this machine.
A repeat reused all 81 boundary images. Model objects are still initialized by
`localize-video`, but all 28 matching scene analyses were reused and no new OCR or translation
inference was required.

Generated inputs, frames, manifests, HTML, caches, and models remain ignored by Git.
