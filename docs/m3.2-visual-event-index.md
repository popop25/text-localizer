# M3.2 partial visual-event index

M3.2 adds a high-frequency, model-free index between exact frame sampling and future text
tracking. It detects when and where pixels change without loading PaddleOCR or M2M100.

## Design

The existing scene index compares a single perceptual hash for the full content ROI at
one-second intervals. It is efficient for choosing OCR representatives, but a localized
scroll can leave stale text boxes alive until the accumulated whole-scene distance crosses
the scene threshold.

The new index:

1. extracts exact 0.2-second samples with the existing FFmpeg round-up policy;
2. crops the configured content ROI;
3. downsizes the grayscale crop to a fixed analysis width;
4. pools absolute pixel differences into a 12 by 8 normalized tile grid;
5. marks tiles whose mean change exceeds the profile threshold;
6. combines consecutive changed intervals into auditable partial or global events.

The output is data/work/{video}-visual-events/visual-events.json. It contains every sample
comparison, tile score above threshold, event range, peak changed ratio, normalized grid
geometry, options, and timing metrics.

Run it independently:

    text-localizer index-visual-events data\input\0.mp4 `
      --profile config\profiles\browser-lecture.yaml `
      --work-dir data\work\0-m32-visual-events

## Separate exclusions

Visual-event exclusions are intentionally independent from OCR exclusions.

The browser lecture's OCR profile masks a middle band that originally avoided unreliable
content around the instructor area. During scrolling, real curriculum text passes through
that band. Applying the same mask to temporal analysis would hide the exact movement M3.2
needs to detect.

The checked-in visual-event profile therefore observes the full content ROI and masks only
the fixed lower-right camera area. Additional visual-only masks can be appended with
--exclude-roi.

## Profile defaults

| Setting | Value |
| --- | ---: |
| Sample interval | 0.2 s |
| Analysis width | 384 px |
| Tile grid | 12 by 8 |
| Tile change threshold | 0.02 |
| Minimum changed tiles | 1 |
| Global-change ratio | 0.35 |

The manifest records these values so later region tracking can reject incompatible input.

The important M3.0 scroll transitions are now visible before OCR:

| Source change | Detected event bracket |
| --- | --- |
| First late-page scroll | 126.2-126.6 s |
| Large curriculum scroll | 140.2-140.6 s |
| Later content scroll | 159.0-159.2 s |

The 126-second event captures the geometry change that left the LangChain curriculum overlay
at the old vertical position. The 140-second event captures the change after which the same
overlay disappeared despite remaining visible in the source.

## Safeguards

- All coordinates remain normalized to the full video frame.
- The original MP4 is opened read-only and remains unchanged.
- Samples, event manifests, and generated measurements stay ignored.
- The command does not initialize or download OCR or translation models.
- Exact sample manifests are reused only when the source fingerprint and interval match.
- Invalid grid dimensions, thresholds, intervals, and exclusions fail before analysis.

## Validation

Synthetic tests cover localized changes, global changes, stable gaps, visual-only exclusion
masks, ROI cropping, normalized grid output, profile parsing, option overrides, and CLI
registration. Ruff, strict mypy, and the complete test suite run without models.

## Remaining boundary

M3.2 identifies changing tiles, not text identities. It does not improve the schema-v1 M3.0
benchmark by itself. A tile can also change because of a pointer, fade, or animation.

M3.3 should use these event brackets to OCR only changed areas, associate matching text
regions across event keyframes, and emit independent region tracks. The M3.0 annotation
recall, keyframe recall, and bbox IoU remain the acceptance gates.
