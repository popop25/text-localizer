# M1.3 timestamped scene tracks

## Goal

M1.3 connects static frame localization to video time without modifying or re-encoding the
input MP4. It samples the full video, detects consecutive scene ranges before loading models,
analyzes only unique scene representatives, and emits editable synchronized overlay data.

## Pipeline

1. FFmpeg extracts fixed-interval PNG samples and writes `frames/samples.json`.
2. ROI-only dHash assigns every sample to a consecutive scene.
3. `scene-index.json` records sample timestamps, estimated scene ranges, and representative
   frames.
4. PaddleOCR and M2M100 run only for scene representatives.
5. Each completed scene immediately keeps its normal M1.1 `regions.json`, preview, and static
   viewer so an interrupted run can resume.
6. `tracks.json` combines every scene time range with its normalized regions.
7. `viewer.html` loads the unchanged source MP4 and switches overlays on `timeupdate`/seek.

The sample interval is also the maximum stated transition precision. A scene detected at a
sample timestamp begins at that timestamp; the true visual transition may have occurred since
the preceding sample.

## Commands

Indexing is model-free and is useful for measuring work before starting CPU inference:

```powershell
text-localizer index-video data\input\0.mp4 `
  --profile config\profiles\browser-lecture.yaml `
  --work-dir data\work\0-m13-timeline `
  --sample-interval 1
```

Localization reuses that work directory and processes only missing representatives:

```powershell
text-localizer localize-video data\input\0.mp4 `
  --profile config\profiles\browser-lecture.yaml `
  --work-dir data\work\0-m13-timeline `
  --output data\output\0-m13-timeline `
  --sample-interval 1
```

The player is `data/output/0-m13-timeline/viewer.html`. It embeds the track manifest but only
references the original video by file URI; no video copy or encoded derivative is created.

## Track schema

`tracks.json` schema v1 records:

- the source video metadata and absolute path;
- the sample interval and frame count;
- one track per consecutive scene with start/end seconds and representative frame;
- the original normalized M1.1 region payload, including source, translation, confidence,
  glossary, cache, and review fields;
- sample/unique/duplicate counts and reuse ratio;
- cumulative OCR, translation, and scene-processing latency;
- current-run latency and the number of analyses reused while resuming.

Translations with `needs_review=true` remain in the JSON for correction but are not rendered as
approved Japanese overlays in the player.

## Measured full-video run

On the 175.275-second Korean browser lecture using a 1-second interval and the checked-in
browser profile:

- FFmpeg produced 175 timestamped samples;
- scene hashing retained 28 representatives and reused 147 samples (84%);
- frame extraction took 9.5 seconds and ROI hashing took 9.7 seconds;
- cumulative representative OCR time was 689.1 seconds;
- cumulative translation time was 714.7 seconds;
- cumulative per-scene processing time was 1,420.6 seconds;
- all 28 scene analyses and time ranges were written;
- an injected resume after scene 21 reused those 21 results without re-running OCR;
- one translation received review flags and is preserved but hidden by the player.

The ignored validation outputs are:

- `data/work/0-m13-timeline/scene-index.json`;
- `data/output/0-m13-timeline/tracks.json`;
- `data/output/0-m13-timeline/viewer.html`.

## Limitations and next step

- Scene boundaries have one-sample uncertainty and should be refined for fast transitions.
- dHash follows visual changes, so animated intros can generate several one-second scenes.
- A flagged translation still needs human correction in an editor before it is approved.
- Tracks are scene-scoped; they do not yet match individual text regions across scrolling or
  moving-camera footage.
- The local player is for review and does not burn subtitles into a final MP4.

The next milestone should add a small track editor for correcting text and time boundaries,
then add boundary refinement around detected transitions without increasing OCR calls.
