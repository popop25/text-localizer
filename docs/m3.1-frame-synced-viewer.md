# M3.1 frame-synchronized viewer

M3.1 removes the browser playback clock as a source of perceived overlay lag. It does not
change OCR, translation, scene boundaries, or the schema-v1 track manifest.

## Diagnosis

The M2 viewer updated overlays only from the HTML media timeupdate event. Browsers may emit
that event less often than decoded video frames, so an otherwise valid track transition can
appear late or uneven during playback.

The editor had a separate problem: its preview remained on the manually selected track while
the video continued into later scenes. The text-editing panel should remain stable, but the
overlay preview should follow playback.

## Frame clock

Both generated HTML tools now use the decoded frame clock:

1. requestVideoFrameCallback supplies the mediaTime of the frame the browser is presenting;
2. the viewer resolves the active track from that mediaTime;
3. the editor resolves the preview track without changing the selected editing panel;
4. the callback immediately schedules the next decoded frame;
5. browsers without the API use requestAnimationFrame only while the video is playing.

The existing seeked, pause, resize, and manual overlay-toggle handlers remain immediate.
timeupdate remains only as a compatibility fallback and cannot overwrite the decoded frame
time in supporting browsers.

Overlay DOM nodes are rebuilt only when the active track changes. The time display is updated
for every presented frame, while static scenes avoid unnecessary overlay layout work.

## Real-video validation

The unedited M2.3 manifest was used to regenerate a viewer and editor for the unchanged
0.mp4. Both outputs contain the decoded-frame callback, mediaTime lookup, and animation-frame
fallback.

The M3.0 data benchmark intentionally remains unchanged:

| Metric | M2.3 manifest after M3.1 viewer generation |
| --- | ---: |
| Annotation recall | 66.67% |
| Keyframe recall | 66.67% |
| P95 boundary error | 37.5 ms |
| Median bbox IoU | 0.50 |

This is the expected result. M3.1 removes presentation-clock lag but does not disguise stale
scene-scoped boxes or missing scrolling text. Those failures remain measurable for the next
milestone.

## Validation

Deterministic tests require both the viewer and editor HTML to contain the decoded-frame
callback, mediaTime use, and fallback loop. The existing timeline, editor, manifest, and
rendering tests continue to run without browser or model downloads.

## Next step

M3.2 should create a high-frequency, model-free partial visual-event index. It should detect
localized changes and scrolling before any OCR call, while keeping the M3.0 benchmark as the
acceptance gate.
